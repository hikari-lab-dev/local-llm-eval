# 課題: 売上レポート集計のリファクタリング

`report.py` の `generate_report` 関数は動作していますが、集計・平均計算・最大値抽出の
複数の責務が1つのループに混在しており読みにくくなっています。
**外部から見た振る舞いを変えずに**、読みやすく整理してください。

## 要求

- 関数シグネチャ `generate_report(sales: list[dict]) -> dict` は変更しないこと（戻り値のキー構成も変えない）。
- 責務ごとに小さな関数へ分割すること（1関数1責務）。
- `else` ブロックを使わないこと（early return や条件式で書き換える）。
- 既存の挙動を保つこと。
  - `amount` が `None` または `0` 以下のレコードは集計から除外する。
  - `category` が無いレコードは `"unknown"` として扱う。
  - `top_item` / `top_amount` は最も金額の大きい1件（集計対象のレコードのみが対象）。
  - 対象レコードが1件も無い場合、`top_item` は `None`、`top_amount` は `0.0`、
    `by_category` / `average_by_category` は空の辞書。

## 制約

- `tests/test_report.py` は既存のテストです。実装がこれを壊さないようにしてください。
- 標準ライブラリのみ使用可能。
